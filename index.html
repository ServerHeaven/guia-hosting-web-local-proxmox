01 · Introducción

¿Por qué hostear localmente en Proxmox?

Si ya tienes un servidor Proxmox en casa, puedes servir webs estáticas (HTML/CSS/JS) desde un contenedor LXC usando apenas ~64 MB de RAM y ~1 GB de disco. Es perfecto para dashboards, documentación, guías, portafolios internos o cualquier sitio que no necesite salir a internet.

⚡

Ultra ligero

Un LXC con Nginx usa ~50-80 MB de RAM. Puedes tener decenas corriendo sin despeinarte.

🔒

Privado

Todo queda en tu red local. Sin DNS público, sin exposición, sin riesgos innecesarios.

🚀

Instantáneo

Latencia de red local (<1ms). Las páginas cargan al instante desde cualquier dispositivo de tu casa.

♾️

Sin límites

Sin cuotas de ancho de banda, sin builds por hora, sin restricciones de tamaño. Tu servidor, tus reglas.

03 · Contenedor

Crear el contenedor LXC

Vamos a crear un contenedor Debian 13 mínimo, no privilegiado y con arranque automático.

Descargar la plantilla

Desde la shell del nodo Proxmox (host):

# Actualizar lista de plantillas
pveam update

# Buscar Debian 13
pveam available --section system | grep debian-13

# Descargar
pveam download local debian-13-standard_13.1-2_amd64.tar.zst

Crear el contenedor

pct create 200 local:vztmpl/debian-13-standard_13.1-2_amd64.tar.zst \
  --hostname webserver \
  --password "TU_PASSWORD_SEGURA" \
  --cores 1 \
  --memory 256 \
  --swap 128 \
  --rootfs local-lvm:4 \
  --net0 name=eth0,bridge=vmbr0,ip=192.168.1.200/24,gw=192.168.1.1 \
  --nameserver 192.168.1.1 \
  --unprivileged 1 \
  --onboot 1 \
  --start 1
⚠️

IP fija: Cambia 192.168.1.200/24 y gw=192.168.1.1 por valores de tu red. Si prefieres DHCP, usa ip=dhcp en su lugar (pero tendrás que buscar la IP luego).

Entrar y preparar el contenedor

# Entrar al contenedor
pct enter 200

# Actualizar paquetes
apt update && apt upgrade -y

# Instalar utilidades básicas
apt install -y curl wget nano rsync unzip
🏔️

Con Alpine Linux (más ligero):

pveam download local alpine-3.20-default_20240908_amd64.tar.xz
Luego usa apk update && apk add nginx en vez de apt.

04 · Servidor web

Instalar y configurar Nginx

Nginx es el servidor web perfecto para contenido estático: usa poca memoria, es extremadamente rápido y la configuración es sencilla.

Instalar Nginx

apt install -y nginx

# Verificar que está corriendo
systemctl status nginx

# Habilitar inicio automático
systemctl enable nginx

Prueba que funciona abriendo http://192.168.1.200 en tu navegador. Deberías ver la página por defecto de Nginx.

Estructura de directorios

/etc/nginx/
  ├── nginx.conf              # Config principal
  ├── sites-available/        # Configs de sitios (todos)
  │   └── default
  ├── sites-enabled/          # Sitios activos (symlinks)
  │   └── default → ../sites-available/default
  └── snippets/               # Fragmentos reutilizables

/var/www/
  └── html/                   # Raíz web por defecto
      └── index.nginx-debian.html

Configurar el sitio principal

Edita el archivo de configuración del sitio por defecto:

server {
    listen 80 default_server;
    listen [::]:80 default_server;

    root   /var/www/html;
    index  index.html index.htm;

    server_name _;

    # Caché agresiva para archivos estáticos
    location ~* \.(css|js|jpg|jpeg|png|gif|ico|svg|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # Compresión gzip
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml;
    gzip_min_length 1000;

    location / {
        try_files $uri $uri/ =404;
    }
}
# Verificar sintaxis y recargar
nginx -t
systemctl reload nginx
05 · Desplegar

Subir tu web al servidor

Tienes varias formas de mover tus archivos HTML/CSS/JS al contenedor. Aquí van de la más simple a la más pro.

Opción A: SCP (desde tu máquina local)

La forma más directa. Desde la terminal de tu PC/Mac:

# Copiar una carpeta entera
scp -r ./mi-web/* root@192.168.1.200:/var/www/html/

# Copiar un solo archivo
scp index.html root@192.168.1.200:/var/www/html/

Opción B: rsync (mejor para actualizaciones)

Solo transfiere los archivos que han cambiado. Ideal para actualizaciones frecuentes:

rsync -avz --delete ./mi-web/ root@192.168.1.200:/var/www/html/
💡

El flag --delete elimina del servidor los archivos que ya no existen en tu carpeta local. Omítelo si no quieres ese comportamiento.

Opción C: Git (clonar directamente en el servidor)

apt install -y git

# Clonar el repo directamente en la raíz web
rm -rf /var/www/html/*
git clone https://github.com/tu-usuario/tu-repo.git /var/www/html/

# Para actualizar después
cd /var/www/html && git pull

Opción D: Descomprimir un ZIP

# Si subiste un .zip con scp
unzip mi-web.zip -d /var/www/html/

Verificar permisos

Después de subir archivos, asegúrate de que Nginx puede leerlos:

# Establecer propietario correcto
chown -R www-data:www-data /var/www/html/

# Permisos: directorios 755, archivos 644
find /var/www/html -type d -exec chmod 755 {} \;
find /var/www/html -type f -exec chmod 644 {} \;

Ahora abre http://192.168.1.200 y deberías ver tu web.

06 · Multi-sitio

Hostear múltiples webs en el mismo contenedor

Nginx soporta virtual hosts, así que puedes servir varias webs desde un solo contenedor, cada una con su propia carpeta y dominio local.

Crear la estructura de carpetas

# Crear directorios para cada sitio
mkdir -p /var/www/guia-openclaw/
mkdir -p /var/www/guia-homeassistant/
mkdir -p /var/www/portafolio/

# Copiar archivos a cada uno
cp index-openclaw.html /var/www/guia-openclaw/index.html
cp index-ha.html /var/www/guia-homeassistant/index.html

# Permisos
chown -R www-data:www-data /var/www/

Método 1: Por subdirectorios (más fácil)

Sirve cada web desde una ruta diferente en la misma IP:

server {
    listen 80 default_server;
    server_name _;

    # Página principal
    root /var/www/html;
    index index.html;

    # Guía OpenClaw en /openclaw
    location /openclaw/ {
        alias /var/www/guia-openclaw/;
        index index.html;
    }

    # Guía HA en /homeassistant
    location /homeassistant/ {
        alias /var/www/guia-homeassistant/;
        index index.html;
    }

    # Portafolio en /portafolio
    location /portafolio/ {
        alias /var/www/portafolio/;
        index index.html;
    }
}

Resultado: http://192.168.1.200/openclaw/, http://192.168.1.200/homeassistant/, etc.

Método 2: Por puertos diferentes

server {
    listen 8081;
    server_name _;
    root /var/www/guia-openclaw;
    index index.html;
}
# Activar el sitio
ln -s /etc/nginx/sites-available/openclaw /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx

Resultado: http://192.168.1.200:8081

Método 3: Por dominio local (el más elegante)

Lo vemos en la siguiente sección.

07 · DNS local

Usar dominios locales personalizados

En vez de recordar IPs y puertos, puedes acceder a tus webs con nombres como guias.lan o openclaw.local.

Opción rápida: archivo hosts

Edita el archivo hosts de cada dispositivo desde el que quieras acceder:

SistemaArchivo
WindowsC:\Windows\System32\drivers\etc\hosts
macOS / Linux/etc/hosts
Android / iOSNo se puede (necesitas DNS local)

Añade estas líneas:

192.168.1.200   guias.lan
192.168.1.200   openclaw.lan
192.168.1.200   ha.lan

Opción pro: Pi-hole / AdGuard Home como DNS local

Si ya tienes Pi-hole o AdGuard Home, puedes crear registros DNS locales para toda tu red (incluido móviles) sin tocar archivos hosts:

1

Pi-hole

Ve a Local DNS → DNS Records, añade guias.lan → 192.168.1.200.

2

AdGuard Home

Ve a Filtros → Reescrituras DNS, añade el dominio y la IP.

Configurar virtual hosts en Nginx por dominio

server {
    listen 80;
    server_name openclaw.lan;
    root /var/www/guia-openclaw;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
server {
    listen 80;
    server_name ha.lan;
    root /var/www/guia-homeassistant;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
# Activar ambos sitios
ln -s /etc/nginx/sites-available/openclaw.lan /etc/nginx/sites-enabled/
ln -s /etc/nginx/sites-available/ha.lan /etc/nginx/sites-enabled/

# Verificar y recargar
nginx -t && systemctl reload nginx

Ahora puedes acceder a http://openclaw.lan y http://ha.lan desde cualquier dispositivo de tu red.

08 · HTTPS local

Añadir HTTPS con certificados auto-firmados

Para redes locales no necesitas Let's Encrypt. Puedes generar certificados auto-firmados o usar mkcert para que tu navegador los acepte sin warnings.

Opción A: mkcert (recomendado, sin warnings)

# Instalar mkcert
# macOS:
brew install mkcert

# Linux:
apt install -y libnss3-tools
curl -fsSL https://dl.filippo.io/mkcert/latest?for=linux/amd64 -o mkcert
chmod +x mkcert && sudo mv mkcert /usr/local/bin/

# Instalar CA raíz local (una sola vez)
mkcert -install

# Generar certificado para tus dominios locales
mkcert openclaw.lan ha.lan guias.lan 192.168.1.200

# Salida: openclaw.lan+3.pem y openclaw.lan+3-key.pem
# Subir los certificados al LXC
scp openclaw.lan+3.pem root@192.168.1.200:/etc/nginx/ssl/cert.pem
scp openclaw.lan+3-key.pem root@192.168.1.200:/etc/nginx/ssl/key.pem
# Crear directorio y proteger la clave
mkdir -p /etc/nginx/ssl
chmod 600 /etc/nginx/ssl/key.pem

Opción B: Certificado auto-firmado (con warning del navegador)

openssl req -x509 -nodes -days 3650 \
  -newkey rsa:2048 \
  -keyout /etc/nginx/ssl/key.pem \
  -out /etc/nginx/ssl/cert.pem \
  -subj "/CN=guias.lan"

Configurar Nginx con HTTPS

server {
    listen 80;
    server_name openclaw.lan;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name openclaw.lan;

    ssl_certificate     /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;

    root /var/www/guia-openclaw;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
nginx -t && systemctl reload nginx
09 · Automatización

Auto-deploy desde Git

Puedes hacer que el servidor se actualice automáticamente cuando hagas push a tu repo de GitHub, o simplemente usar un cron que haga pull periódicamente.

Método simple: cron + git pull

# Editar crontab
crontab -e

# Añadir esta línea (pull cada 5 minutos)
*/5 * * * * cd /var/www/guia-openclaw && git pull origin main --quiet

Método avanzado: webhook con GitHub

Instala un listener ligero que recibe webhooks de GitHub y ejecuta git pull automáticamente:

apt install -y webhook

# Crear config del webhook
cat > /etc/webhook.conf << 'EOF'
[
  {
    "id": "deploy-openclaw",
    "execute-command": "/opt/deploy.sh",
    "command-working-directory": "/var/www/guia-openclaw"
  }
]
EOF

# Crear script de deploy
cat > /opt/deploy.sh << 'EOF'
#!/bin/bash
cd /var/www/guia-openclaw
git pull origin main
chown -R www-data:www-data .
EOF

chmod +x /opt/deploy.sh

Método one-liner: script de deploy con rsync

Crea un alias en tu máquina local para desplegar con un solo comando:

# Añadir alias
alias deploy-openclaw="rsync -avz --delete ./mi-web/ root@192.168.1.200:/var/www/guia-openclaw/"
alias deploy-ha="rsync -avz --delete ./mi-otra-web/ root@192.168.1.200:/var/www/guia-homeassistant/"

Ahora solo ejecutas deploy-openclaw desde tu terminal y listo.

10 · Seguridad

Securizar el servidor

Aunque es una web local, aplicar seguridad básica es buena práctica y te protege de dispositivos comprometidos en tu red.

Firewall con UFW

apt install -y ufw

# Políticas por defecto
ufw default deny incoming
ufw default allow outgoing

# Permitir SSH solo desde tu red
ufw allow from 192.168.1.0/24 to any port 22

# Permitir HTTP y HTTPS desde tu red
ufw allow from 192.168.1.0/24 to any port 80
ufw allow from 192.168.1.0/24 to any port 443

# Activar
ufw enable
ufw status

Headers de seguridad en Nginx

Añade esto dentro del bloque server:

# Headers de seguridad
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-XSS-Protection "1; mode=block" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;

# Ocultar versión de Nginx
server_tokens off;

Desactivar SSH con password (opcional)

PermitRootLogin prohibit-password
PasswordAuthentication no
PubkeyAuthentication yes
systemctl restart sshd
🔒

Antes de desactivar password auth, asegúrate de haber copiado tu clave pública SSH al contenedor con ssh-copy-id root@192.168.1.200. Si no, perderás el acceso.

11 · Troubleshooting

Solución de problemas

ProblemaCausaSolución
403 Forbidden Permisos incorrectos chown -R www-data:www-data /var/www/
404 Not Found Ruta incorrecta o falta index.html Verifica root en config de Nginx y que el archivo existe
Página de Nginx por defecto Config no activada o mal escrita Revisa symlink en sites-enabled, ejecuta nginx -t
No se resuelve el dominio .lan DNS no configurado Revisa /etc/hosts o la config de Pi-hole / AdGuard
Connection refused Nginx no está corriendo systemctl start nginx, revisa logs con journalctl -u nginx
ERR_SSL_PROTOCOL_ERROR Puerto 443 sin SSL configurado Verifica que los certificados existen y las rutas son correctas
No puedo acceder desde otros dispositivos Firewall del contenedor ufw status — asegura que puerto 80/443 está abierto
